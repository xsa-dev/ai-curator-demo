# AI-куратор онлайн-школы · демо на моках

Готовая демонстрация Next.js + TypeScript без Docker, серверной БД и API-ключей. По умолчанию включён мок-транспорт: ответы формируются локально, история и предпочтения сохраняются в localStorage браузера. В интерфейсе это явно указано.

## Локальный запуск

Node.js 22+:

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. `.env` для демонстрации не нужен.

## Что работает

- Переключение между `client_1`, `client_2` и `admin`.
- Персональные планы по разным целям и предпочтениям.
- Контекст текущего диалога.
- Сохранение предпочтений при сообщениях «Я предпочитаю практические задания», «Моя цель: Rust» и «Запомни level: средний».
- Новая сессия без потери долговременной памяти.
- Просмотр, добавление, изменение и удаление предпочтений.
- Административная панель управления всеми тремя demo-аккаунтами.
- **Новая функция: поиск по ключам и значениям предпочтений**, без учёта регистра и с обработкой пустого результата.

Данные сохраняются только в текущем браузере и профиле сайта. Они не синхронизируются между устройствами; очистка данных сайта удаляет их. Данные разных посетителей изолированы. Мок-ответы не являются результатами внешней LLM. Переключение ролей — демонстрация интерфейса, а не настоящая авторизация.

## Проверки без Docker

```bash
npm run typecheck
npm test
npm run test:coverage
npm run build
```

`tests/demo.test.ts` проверяет контекст, межсессионную память, персонализацию, upsert, CRUD администратора, ограничения демонстрационных ролей, восстановление хранилища и новую функцию поиска.

GitHub Actions `.github/workflows/test.yml` запускает проверки при `push` и Pull Request. Контейнеры и секреты для workflow не нужны. Покрытие относится к мок-транспорту; интерфейс браузерными E2E-тестами не покрыт.

## Публикация на Vercel

1. Загрузите содержимое этой директории в GitHub-репозиторий.
2. Импортируйте репозиторий в Vercel, framework — Next.js, Node.js — 22.x.
3. Используются `npm ci` и `npm run build`, как указано в `vercel.json`.
4. Переменные окружения не требуются: мок-режим включён по умолчанию. При необходимости явно задайте `NEXT_PUBLIC_DEMO_MODE=true`.
5. Подключённый Git-репозиторий позволит Vercel автоматически создавать Preview для веток и production deployment для `main`.

Деплой не создаёт базы, не вызывает LLM, не требует платных сервисов. Реальные персональные данные в демо не вводите.

## Сохранённая SQL/LLM реализация

Исходные Prisma-модели, миграции, сервисный RBAC, API Routes, Tool Calling и интеграционные тесты сохранены. Для отдельного полноценного режима нужно задать `NEXT_PUBLIC_DEMO_MODE=false`, настроить переменные из `.env.example`, подключить PostgreSQL и LLM, применить миграции и seed. Перед реальным использованием замените демонстрационный `x-user-id` на проверяемую серверную сессию.

Дополнительные команды:

```bash
npm run test:pglite  # SQL-интеграции на временном PostgreSQL WASM, без Docker
npm run test:sql     # SQL-интеграции против отдельной тестовой PostgreSQL
npm run test:live    # Внешняя LLM, требуется API-ключ и тестовая БД
```

`test:sql` и `test:live` требуют отдельного `TEST_DATABASE_URL` с `test` в имени и `TEST_DATABASE_RESET=yes`; содержимое этой тестовой БД удаляется. В CI демо они не запускаются.

## Учебный процесс PR и CI

Для задания нужен отдельный цикл: feature branch → тест поиска → намеренно падающий тест → красный GitHub Actions → исправление → зелёный GitHub Actions → PR → merge → автоматическое обновление Vercel. Файл `HOMEWORK.md` содержит чек-лист; наличие workflow в исходниках ещё не означает, что удалённые запуски уже состоялись.
